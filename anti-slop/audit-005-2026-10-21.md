## HIGH (Hard Gate)

**1. R-38 and C-5, the fairness copy promises more than the data can support.**
`components/games/seed-manager.tsx:12` says the old seed is revealed so "any past round can be re-checked", and `app/games/page.tsx:188` says a member can "re-check every past result". `game_seeds` keeps only the current seed and one `prev_server_seed`; `lib/games/engine.ts:83-84` overwrites that previous seed on every rotation. A second rotation destroys the first revealed seed, so older bets become impossible to check. Fix: archive every revealed seed in a `game_seed_reveals` table, backfill the current previous seed, and change the copy to "any round whose server seed has been revealed". This is a trust claim, not cosmetic copy.

**2. R-26 and C-2, there is no verifier action and the history payload cannot support one.**
The fairness panel can save and rotate seeds but has no control that recomputes a round. The instant and Crash history rows have no verify action. `/api/games/history` selects only `game_bets` and omits `params`, so even a manual checker cannot re-derive the round. Mines writes to `game_rounds`, which the history route never reads. Fix: add a dedicated `/games/verify` page, a `/api/games/verify` endpoint that returns settled `game_bets` plus settled Mines rounds with `params`, `result`, and the revealed server seed when available, and links from the fairness panel and game history.

**3. R-27 and C-4, a failed history request looks like an empty history.**
`components/games/game-view.tsx:140-146` and `components/games/crash-view.tsx:257-263` catch every history error and leave the list empty. The UI then says "No rounds here yet", which is false when the request failed. Fix: the verifier and history lists need explicit loading, error with retry, and empty states. The verifier must also distinguish a current seed that is not revealed yet from an older seed whose record is missing.

---

## MEDIUM (resilience)

**4. C-4 and R-27, verification is unreachable when the casino is closed.**
`app/api/games/seed/route.ts:18` and `:29` return 403 when `games_enabled` is false, and the game pages return 404. A member cannot inspect old bets when the operator pauses the tables. Fix: make `/games/verify` independent of `games_enabled`, allow the seed read and rotation as fairness operations rather than bets, and add a link from the account page so the verifier remains reachable.

## LOW (Quality Locks)

**5. R-31, the verifier trust model and seed retention have no written reason.**
`DESIGN.md` explains the casino motion but does not say why the verifier recomputes in the browser, how revealed seeds are retained, or how payout scaling differs from outcome verification. Fix: record three short reasons in `DESIGN.md`: the player recomputes with Web Crypto without trusting a verify endpoint, revealed seeds are archived so old receipts stay checkable, and the verifier checks the seed-derived outcome while the recorded paid multiplier remains separate because site edge and caps can change it.
